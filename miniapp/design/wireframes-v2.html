혼자도, 함께도 살림잇다

가구 유형 설정과 1인가구 전환 화면 기획안 · 알림 정책은 이번 범위에서 제외

기획 제안: 구성원은 그대로, 관리 권한만 양도. 관리자는 기존 가구를 떠나 새 1인가구를 시작해요. 기존 가구의 물품과 기록은 남은 구성원이 계속 사용해요.

01. 처음 시작할 때

가구 유형을 먼저 선택하고 이름을 설정해요. 초대 링크로 들어온 사람은 초대받은 가구 참여 흐름을 따라가요.

02. 개인 설정 → 가구 유형 변경

관리자 · 나 포함 3명인 다인가구 기준. 양도와 1인가구 시작은 마지막 확인에서 한 번에 완료해요.

03. 클릭해서 흐름 확인하기

화면 데모 · 실제 데이터 변경 없음

조건을 바꿔 관리자 양도, 구성원 탈퇴, 혼자 남은 가구의 전환을 확인할 수 있어요.

양도 대상을 선택하고 최종 확인을 눌러보세요. 확인 전에는 기존 가구가 유지돼요. 실제 구현에서는 양도 대상이 이미 탈퇴한 경우 재선택을 안내해야 해요.

04. 분기 및 데이터 정책 제안

상황사용자 흐름기존 데이터 · 초대 코드
관리자 + 다른 구성원 있음양도 대상 선택 → 확인 → 기존 가구 탈퇴 + 새 1인가구 생성물품·기록·남은 구성원 유지. 기존 가구 초대 코드 전부 만료.
일반 구성원탈퇴 확인 → 새 1인가구 생성. 양도 단계 없음.원래 가구의 물품·기록 유지. 다른 사람의 초대 코드는 유지하는 안을 제안.
혼자 남은 관리자유형 변경 확인 → 현재 가구를 1인가구로 변경물품·기록 유지. 유효한 초대 코드 전부 만료.
1인가구 → 다인가구유형 변경 확인 → 같은 가구를 다인가구로 변경 → 선택적으로 초대물품·기록 유지. 변경 직후 혼자여도 다인가구 유지.
동일한 유형 선택현재 유형 표시, 저장 비활성화변경 없음. 초대 코드 유지.
양도 대상 탈퇴 · 권한 변경완료 처리하지 않고 구성원 정보를 다시 조회 → 재선택 안내양도·탈퇴·가구 생성·초대 만료를 모두 취소.
처리 실패 · 응답 유실실패 시 기존 상태 유지. 응답 유실 시 처리 결과 조회 후 재시도.중복 요청으로 새 1인가구가 여러 개 생기지 않도록 처리.

초대는 다인가구에서만

1인가구의 멤버 화면에는 ‘다인가구로 바꾸고 초대하기’를 제공해요. 기존 초대 링크 접근 시 ‘가구 설정이 변경되어 만료된 초대예요’와 새 코드 요청 안내를 보여줘요.

마지막 확인 전에는 변경 없음

뒤로 가기·취소는 선택만 버려요. 처리 중 중복 제출을 막고, 기존 초대 코드 수락과 전환이 동시에 일어나도 전환 후 코드가 사용되지 않게 보장해야 해요.

가구가 여러 개일 때

개인 설정에 변경 대상 가구 이름을 명시해요. 이번 안은 선택한 가구에만 적용하고, 완료 후 새 1인가구를 현재 가구로 열어요. 다른 가구 소속은 유지해요.

확정이 필요한 정책

이 안은 양도 상대의 별도 수락 없이 최종 확인 시 관리 권한을 넘겨요. 일반 구성원의 탈퇴는 ‘가구 유형 변경’과 구분해 원래 가구 초대 코드를 유지해요. 두 정책은 출시 전 확정이 필요해요.
